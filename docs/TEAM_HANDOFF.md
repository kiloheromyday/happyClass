# 三人组交付分工建议

以下是后续任务安排，不是已经完成的贡献记录。成员姓名、实测结果、提交记录和课程信息需由本人实际完成后填写。已有功能与测试结果见 README.md 和 TEST_REPORT.md。

## 成员一：你，负责整合与演示主线

核对参考指导书和教师实际要求，确认数据库产品与提交格式是否被强制指定；当前本机使用 SQLite。熟悉账号角色、课程名单、反馈、AI、学伴、匿名问题和课堂小结的连接关系。接收另外两人的问题记录，安排修复、复验与最终打包；最终冻结一份经过复验的源码包。

交付：需求对照表最终版、修订后的功能说明、最终交付目录，以及本人实际完成的工作记录。答辩重点解释“为什么这样分层”“怎样限制教师课程权限”“匿名问题与数据库内部关联的区别”。

## 成员二：真实页面与设备验收

用真实浏览器按 FINAL_CHECKLIST.md 验收学生、教师和管理员流程，记录浏览器版本、时间、操作、实际结果和截图。覆盖长用户名、窄屏、断网重试；学生匿名提问，教师回应/解决，学生查看回应；教师保存反思并导出小结。确认学生不能进入教师功能、教师不能访问其他教师课堂。

由本人主动开启并授权摄像头，检查预览、识别、停止、隐藏页面与切换课堂后的设备释放；有条件时比较不同光照和距离。只记录实际观察，不把情绪识别结果当作心理诊断，不编造准确率。

交付：真实页面验收表、必要截图、问题与复验记录、物理摄像头观察记录。自动化测试已经通过的部分仍需与真实点击区分。

新增个人空间也由本轮验收覆盖：学生写课堂笔记、保存收获与下一步、标记已回顾、切换个人回顾时间并导出笔记；核对未保存提示和删除二次确认；确认其他账号不能读取该笔记。步骤见 PERSONAL_NOTES.md。

新增加入码流程：教师生成，未入名单的学生输入加入，重复输入不重复，教师更换或停用后旧码不可用；检查提前加入仍不能提前提交反馈。个人回顾还需切换课堂、打开近期笔记、导出回顾及查看完整 90 天趋势。步骤见 JOIN_CODES.md 和 PERSONAL_NOTES.md。

0.13.0 调整后，请在“我的课程”验收添加与加入码管理，日常“我的课堂”不再出现码。核对一次添加后续课堂自动安排、默认进行中与刚结束筛选、结束后 30 分钟评价边界，以及全部课堂模式不会开放过期评价。旧名单仅回填课程关系，不改动旧课堂安排。

0.14.0 还需点击个人回顾的日期节点，核对当日反馈/笔记与课堂范围，试用零记录日、日期框、键盘切换、长图滑动、分页及打开笔记。快速切换日期或课堂后不应出现旧详情。自动交互检查不能替代真实浏览器布局验收。

0.15.0 增加个人主页验收：选择头像、裁剪预览、取消与保存、更换和恢复默认，检查刷新和再次登录后保留；核对侧栏/学伴头像同步、匿名留言不出现作者头像、未保存草稿提示与概览跳转。安装说明新增 Pillow，部署复现时应记录。

0.16.0 增加课程卡片与详情验收：点击课程查看真实课堂安排、状态筛选和本人反馈/笔记统计，从非首节课堂进入评价、笔记和回顾后核对上下文；检查新笔记预关联、未保存保护及返回课程详情。教师加入码在本门课程详情内管理。补录宽屏/窄屏、长课程名、键盘操作和空课程效果，说明见 COURSE_DETAILS.md。

0.17.0 教师端与学生端对应验收由两位组员分别登录完成：教师安排课堂→学生课程详情出现；学生提交问题→教师待办出现→回应后学生可读；教师保存指引草稿→学生不可见→发布后可读→学生进入对应笔记/回顾→撤下后刷新消失。核对教师反思草稿保护、课堂功能页、指定课堂看板/课程统计、只读名单与重试不重复安排。见 TEACHER_WORKSPACE.md 的对应表。

0.18.0 演示时可用登录卡片开发者模式快捷切换师生；请用新建的隔离成员测试管理操作，勿改动他人账号。演示服务启动方式与默认关闭边界见 DEVELOPER_MODE.md；成员管理不是普通学生/教师的角色权限，报告中应写清楚本地演示能力。

学伴留言墙验收需分别试用匿名与允许点击来源的发布方式；核对身份不会出现在列表数据里、匿名无来源入口、公开来源由点击获取；验证墙主删除、作者编辑与解除关系后的作者撤回。步骤见 BUDDY_WALL.md。

## 成员三：报告、部署复现与视频

依据 REQUIREMENTS.md、DESIGN.md、DEPLOYMENT.md、TEST_REPORT.md 和 DEMO_AND_REPORT.md 整理课程报告，补真实组号、姓名、分工、限制和 AI 辅助使用说明。若课程要求 Word/PDF，再据正式格式排版。

在另一目录或另一台电脑按部署说明复现环境，创建新账号与测试课堂，记录依赖、启动和数据库初始化结果。安排 5～8 分钟视频脚本并录制，展示核心流程及匿名问题—教师回应—课堂小结，避免录入密码、令牌或私人信息。

交付：课程报告、实际部署复现记录、可回放演示视频、提交材料清单。

## 建议完成顺序

1. 成员一确认教师的硬性要求；成员二开始真实页面验收；成员三整理报告框架并复现部署。
2. 成员二提交问题记录，由成员一整合修复；受影响流程必须复验。
3. 冻结功能后录视频、更新报告截图及最终测试结果，保证展示与提交源码一致。
4. 三人各自确认实际贡献、课程信息、视频、报告、源码和建表/接口资料齐全。不得补造 Git 历史、签到或个人贡献。

当前自动检查与本机接口验证已完成，真实浏览器点击、屏幕布局、物理摄像头、跨环境复现、正式报告信息和视频仍需实际完成；这些是三人接下来最有价值的工作。
