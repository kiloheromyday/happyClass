# 第三阶段课程课堂与表情反馈

本阶段完成管理员安排课堂、学生表情提交、教师查看反馈的完整业务链路。未加入模拟课堂或预设账号，页面从本地数据库读取真实记录。

## 新增功能

- 管理员为有效教师创建课程，创建课堂并指定课程、开始结束时间、教室与班级。
- 管理员查询有效教师学生账号，替换课堂名单；最多一次安排 500 个学生，重复 ID 自动去重；无效、非学生或停用账号导致整次保存失败并保留原名单。
- 学生只能看见安排给自己的课程与课堂，只能向正在进行的课堂提交；课堂开始时允许提交，结束时不再允许。
- 七类手动表情：开心、平静、低落、生气、惊讶、担忧、反感。用户 ID、来源和记录时间由后端生成，学生不能伪造 AI 来源、其他用户或时间。
- 提交必须带 UUID 请求标识，同一用户重复请求返回原记录，内容不一致则拒绝；即使网络响应丢失后重试也不会重复入库。
- 学生查看自己的分页历史。移出课堂名单不会删除其历史；学生无法查看其他学生的明细。
- 教师只能访问所授课程的课堂、名单、反馈明细和统计，管理员可访问全部。提供七类情绪分布、总记录数、手动与 AI 数量、去重反馈学生数。
- 所有汇总按请求读取当前数据库，点击页面“刷新”获取最新结果；尚未加入自动轮询、推送或趋势图。

## 新增接口

| 方法与地址 | 权限与说明 |
| --- | --- |
| GET /api/courses | 当前角色范围内课程 |
| POST /api/admin/courses | 管理员创建课程 |
| GET /api/admin/people | 管理员查询有效教师与学生，返回 ID、用户名与角色 |
| GET /api/sessions | 学生仅名单内课堂；教师仅所授课堂；管理员全部 |
| POST /api/admin/sessions | 管理员创建课堂 |
| GET /api/sessions/{id}/roster | 管理员或该课堂教师 |
| PUT /api/admin/sessions/{id}/schedule | 管理员原子替换名单 |
| POST /api/emoji | 学生提交表情，首次 HTTP 201，重复同请求 HTTP 200 |
| GET /api/emoji/history | 按角色隔离的历史，可选 session_id；limit 最大 100 |
| GET /api/sessions/{id}/statistics | 管理员或该课堂教师 |

写操作保留第二阶段来源校验。课堂时间必须携带时区、结束晚于开始且创建时尚未结束。数据库保存 UTC 毫秒格式，页面按电脑本地时区显示。已结束课堂名单不可编辑。

## 数据库与事务

新增 emoji_submission_keys 表，将用户与请求标识绑定到唯一表情记录；通过幂等建表自动升级，不删除已有表与数据。名单替换、表情提交、课程与课堂创建使用写事务，验证与写入在同一事务内完成。学生历史查询始终以登录用户 ID 限制；教师查询通过课程 teacher_id 限制。

## 验证结果

2026 年 11 月 2 日：

- 后端共 38 项测试通过，覆盖第二阶段认证回归，以及管理员创建 → 安排名单 → 学生提交 → 教师统计全流程。
- 新增验证涵盖无效名单回滚、去重、开始结束时间边界、未安排拒绝、教师跨课程访问拒绝、学生历史隔离、名单移除后历史保留、请求重复去重、伪造来源/用户/时间拒绝、空汇总与分页。
- Vue 生产构建成功。
- Vue 服务端渲染检查通过：登录页、三个角色工作台、三个角色课堂面板均能生成页面，角色专属菜单与表单正确区分。
- 真实浏览器截图、点击与手机布局检查仍未完成；服务端渲染检查不能替代浏览器交互验证。
- 未下载 AI 模型或增加运行依赖。

当前分布按记录条数计数，同一学生允许多次反馈，不能把情绪分布比例当作学生人数比例。反馈人数独立按手动记录的用户 ID 去重。AI 服务尚未实现，因此当前没有实际 AI 反馈记录。
