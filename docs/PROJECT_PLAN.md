# 范围与架构

参考资料用于确定课程项目的主要模块，用户要求不必逐项照搬。当前选择浏览器客户端，学生、教师和管理员共用前端工程，后续依据登录角色展示功能，并在后端强制校验权限。

## 技术方案

前端 Vue 3 + Vite；后端 Python + FastAPI；本地开发使用 SQLite。AI 为独立 Python 服务，已采用 OpenCV Haar 检测与 FER+ ONNX CPU 推理。公开样例与独立采集程序链路已验证，物理摄像头还需用户主动开启后实测。

当前使用 SQLite 减少部署依赖。若最终课程验收要求 PostgreSQL/MySQL，第二阶段应先引入 SQLAlchemy 和版本迁移，再实现业务接口；当前 SQL 为 SQLite 方言，不能直接当作 PostgreSQL 初始化脚本使用。

## 第一阶段交付范围

已完成新项目目录、独立依赖、前端构建、数据库初始化与持久化验证。第二阶段账号功能也已实现，详见 PHASE2.md。

## 数据与接口原则

核心实体为 User、Course、ClassSession、ScheduleUser、EmojiRecord、AuditLog。表情来源区分 MANUAL/AI，AI 结果必须有 0～1 的置信度；人工记录必须关联用户。表结构含外键与枚举约束，服务层已实现角色、课程归属、名单、时间和重复请求规则。

JSON 响应采用 `code/message/data`。当前已提供账号、课程课堂、名单、表情历史、实时看板、多维统计与 CSV 导出。导出成功返回 CSV 文件，失败返回统一 JSON 错误；具体契约由运行中的 OpenAPI 展示。记录使用 UTC 的固定格式写入，界面显示时再转换到用户时区，统计趋势则明确按 UTC 分桶。

## 环境策略

以本机方式运行项目，Docker 为可选扩展。项目虚拟环境已装好 AI 依赖和模型，不改动系统 Python；CPU 推理通过，不依赖 GPU。源码包不含依赖、权重、数据库或密钥，由脚本准备环境与新凭据。
