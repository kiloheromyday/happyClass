# 本地演示开发者模式（0.18.2）

0.19.0 起演示管理员默认进入“开课总览”，查看全部课程课表与评价；新增演示课程及合成评价的补充方式见 CAMPUS_DEMO.md，演示身份切换方式保持不变。

本机演示时，在登录卡片底部点击“开发者模式 → 开启演示开发者模式”。随后可直接选择演示学生、演示教师或演示管理员，无需填写密码。登录后同样的切换栏保留在工作台顶部，切换会重新进入所选身份的工作台；管理员可以管理课程、课堂、学生名单及查看用户列表。学伴是学生之间的好友关系，位于学生端“好友学伴”功能中，不作为单独的登录身份。

该模式是本机演示管理能力。选择演示管理员会登录专用管理员账号；学生、教师账号本身的角色与权限保持不变。它可以管理本数据库其他学生和教师的基本账号信息，因此只适用于自己控制的本地演示环境。默认启动关闭；启用时要求请求实际来自回环地址，且 Host 为 localhost/127.0.0.1/::1，不信任转发头。

## 启动和关闭

普通启动 `scripts/start.ps1` 不主动启用演示模式，环境变量默认 `EMOJI_DEMO_MODE=0`。本机演示启动：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-demo.ps1
```

这会设置当前服务进程 `EMOJI_DEMO_MODE=1` 并绑定 127.0.0.1。它不会创建、重置或预置任何账号密码。使用前应已有 `demo_student`（学生）、`demo_teacher`（教师）、`demo_admin`（管理员）；仅状态正常且角色匹配时出现在切换列表。缺少演示管理员时，可在本机运行 `.\.venv\Scripts\python.exe -m backend.manage create-user --username demo_admin --role ADMIN`，按提示设置自己的密码；不支持通过网页注册管理员。原有 demo_buddy 是普通学生测试账号，可用于好友功能测试，不提供独立“学伴端”，也不在快捷登录列表中。现有本机已具备演示账号，源码包不包含本机账号与数据库。

网页的“关闭开发者模式”立即撤销当前浏览器的演示管理能力并隐藏快捷按钮，保留当前普通登录；账号原密码不变。关闭后可再次展开并开启。要关闭整个服务的演示能力，停止该服务并在 EMOJI_DEMO_MODE 未开启的进程中正常启动。不要将演示模式通过反向代理或端口转发对外提供。

## 成员管理

点击“管理学生与教师”，支持按用户名、昵称、邮箱查找，按角色和状态筛选、分页。

- 新建学生或教师：填写用户名、角色、邮箱（可选）及初始密码。密码规则与普通注册一致，不允许创建管理员。
- 编辑资料：仅修改昵称和邮箱，保留用户名、角色、其他学习资料、头像、课程与历史数据。过时资料会返回冲突提示，编辑内容保留；可放弃成员修改并查找刷新后再编辑。
- 停用或启用：需再次确认；停用撤销该成员原有登录，历史数据保留。启用不会恢复已撤销的旧会话。
- 重设密码：填写两遍并再次确认后保存，该成员所有旧登录失效。密码不在列表、返回数据或日志中展示。
- 固定演示账号受保护，不能从此入口改资料、停用或重设密码。管理员账号不出现在成员列表，也不能通过本接口修改。没有硬删除或角色转换入口。

学生/教师/管理员的普通登录本身不能调用演示成员管理。必须先在已开启本地演示服务上主动开启开发者模式，获得独立的 HttpOnly、SameSite=Strict 会话能力。有效期 8 小时，可重新开启；关闭或到期即失效。每次管理操作都检查本地开关和能力凭据，写操作同时检查来源与请求头并记录演示审计。

## 草稿与身份切换

存在未保存的个人资料、头像预览、笔记、留言、问题、教学指引、反思或课堂安排时，快捷切换暂时禁用，需先保存或放弃修改。成员管理表单自身也有草稿保护。成员读取或写入期间不切换身份，重设/停用均有确认步骤。普通网页登录和退出同样不能绕过未保存的成员表单。

切换只允许固定白名单里的 demo 身份，服务端创建实际普通角色会话并撤销当前浏览器的旧角色会话。不会将现有会话改写成另一角色，也不支持任意成员免密码登录。更换身份后旧工作台卸载，原请求被取消，避免残留原角色界面。

## 接口与验证

`/api/demo/status` 只返回是否开放、当前能力是否有效及可用的固定演示账号，不返回令牌。`POST /enable`、`POST /disable`、`POST /login` 用于主动开启、关闭和切换。成员管理位于 `/api/demo/members`，包括 GET/POST、PUT `/{id}`、PUT `/{id}/status`、PUT `/{id}/password`。

新增 `demo_access_sessions` 仅保存随机能力令牌的哈希及到期时间；不更改业务数据模型或原账号密码。默认关闭、非本地拒绝、源校验、白名单、能力到期/撤销、受保护账号、成员搜索/分页、资料冲突、停用与密码重设撤销登录等由 `tests/test_demo.py` 覆盖。`node tests/test_demo_interactions.cjs` 使用实际 App 组件和隔离数据验证入口、成员管理、确认、过期续开、草稿保护、身份重挂载及请求取消。

真实浏览器中还应检查登录卡片展开高度、窄屏成员操作、学生/教师/管理员切换及关闭模式。自动组件和接口检查不能代替真实浏览器布局验收。
