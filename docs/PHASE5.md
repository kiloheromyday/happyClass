# 第五阶段：账号管理与课堂表情识别

## 使用入口

管理员登录，在“用户列表”展开“创建教师或学生账号”，填写用户名、角色与初始密码。创建成功后用户列表刷新，管理员保持原登录身份。首次管理员仍通过本机管理命令创建，网页不能创建管理员。新账号可在“账号安全”修改初始密码。

教师或管理员进入课堂详情，选择正在进行的课堂，在“课堂表情识别”手动点击“开启识别”。允许浏览器摄像头权限后显示本机预览，约每 3 秒提交一帧。默认画面约 640×480，上传前限制至 960×720。也可选择 JPEG 图片进行单次识别。刷新页面可重新检查服务状态。

切换课堂、离开页面、隐藏标签页、主动停止时释放摄像头并取消请求。权限弹窗尚未完成时离开页面，后续即使权限获准也会立即释放设备。标签页恢复可见后需再次手动开启。请求按顺序发送，不并发采样；临时服务错误重试同一帧并复用标识，最多连续失败三次后停止。

## 环境与配置

基础环境之外使用 OpenCV Headless、NumPy 和 ONNX Runtime CPU。无需 Docker、GPU 或大型深度学习框架。本机已安装并下载 FER+ 模型，模型约 35 MB；依赖精确版本见 `ai_service/requirements-ai-lock.txt`。

首次在其他电脑运行 `scripts/setup-ai.ps1`，随后分别启动 `scripts/start.ps1` 与 `scripts/start-ai.ps1`。准备脚本可接受 `-UvPath`，也可通过 pip 安装锁定版本，再执行 `scripts/prepare_ai.py`。

默认地址：网页 http://127.0.0.1:18080/ ，AI http://127.0.0.1:18081/health 。只绑定本机。独立 AI 服务使用 Bearer 密钥认证，密钥保存在忽略版本管理的 `data/ai-service.token`，不会发送给浏览器。也可给两个进程设置相同的 `EMOJI_AI_TOKEN`（至少 32 字符）。请勿将整个本地 data 文件夹公开分享。

`EMOJI_AI_URL` 默认 `http://127.0.0.1:18081`；`EMOJI_AI_MIN_CONFIDENCE` 默认 0.70，允许 0.50～1.00。通过进程环境变量配置，`.env` 不会自动加载。更改后重启相应服务。模型校验失败或依赖缺失时，服务明确返回未就绪，不声称识别可用。

## 识别与保存规则

采用 OpenCV Haar 正面人脸检测及官方 MIT 许可的 FER+ ONNX 模型，CPU 推理。模型文件 SHA256 在每次加载时检查；来源、预处理与许可见 `ai_service/models/README.md` 和 `LICENSE.txt`。

上传仅接受不超过 1,000,000 字节的 JPEG。解码前检查图片头，宽度 32～1920、高度 32～1080。最大分析 12 张人脸，优先面积较大者；结果区分别展示检测数与实际分析数。输入为灰度 64×64、float32 原始像素，输出经过稳定 softmax 得到概率。八类输出中的 contempt 被过滤，不强行映射到已有七类表情。

只有超过或等于阈值的支持类别入库；`source=AI`，`user_id=NULL`，保留置信度、课堂、来源设备标记与时间。不会将人脸对应到学生账户。不保存原始照片、视频、人脸截图或人脸特征。重复采样会产生多条记录，不能当作人数；模型概率也不等于经过真实课堂校准的准确率。

后端先检查教师课程归属和课堂时间，识别完成后在事务内再次检查。课堂在推理期间结束时不会写入。帧 UUID、图片摘要与返回计数在 `ai_frame_keys` 中记录，重复请求返回原结果，内容不一致的同一标识返回冲突。每账号 5 分钟最多 100 次新识别请求。学生不能上传课堂识别结果或查看他人匿名记录。

## 新接口

| 方法 | 地址 | 权限及用途 |
| --- | --- | --- |
| POST | `/api/admin/users` | 管理员创建教师/学生，沿用密码与用户名规则、来源校验及审计 |
| GET | `/api/ai/status` | 教师/管理员检查识别服务及阈值 |
| POST | `/api/sessions/{id}/ai-frame` | 任课教师/管理员，JPEG 原始请求体，`X-Frame-ID` UUID，需来源校验 |
| GET | AI 服务 `/health` | 返回模型、认证配置与 ready 状态 |
| POST | AI 服务 `/infer` | 独立 Bearer 密钥，返回匿名分类与概率，不直接操作数据库 |

## 验证结果（2026-11-02）

- 79 项 Python 检查通过，包含教师/学生越权、来源校验、课堂时间、置信度边界、重复帧、匿名保存与管理员创建账号。
- Vue 页面渲染、既有看板轮询、摄像头生命周期检查通过；前端生产构建成功。
- 实际 ONNX 加载和推理通过，空白图返回无人脸。
- 使用 scikit-image v0.19.3 的 NASA 公共领域 astronaut 样例，真实模型检测 1 张人脸并输出 HAPPY（约 99.999% 模型概率）。
- 后端通过 HTTP 调用独立运行的 AI 服务，识别结果在隔离数据库中保存 1 条并进入统计；同一帧重复请求后仍为 1 条，损坏 JPEG 返回 422。正式数据库账号和记录数量未改变。
- 本机后端及 AI 服务健康检查通过，模型已就绪。

未自动访问用户摄像头；实际设备授权与浏览器预览仍需用户点击后实测。当前页面操作通过组件和生命周期检查，未宣称完成真实浏览器自动操作。遮挡、侧脸、光照、距离和训练数据差异会影响识别结果，课堂反馈应结合学生主动表达理解。
