# 个人资料与好友学伴

本地应用版本 0.8.0，2026 年 11 月 3 日添加并扩展多维搜索。

## 个人资料

所有角色从“个人资料”编辑昵称（32 字）、联系邮箱、简介（160 字）、学习兴趣（80 字）、专业方向（60 字）、年级（20 字）、学习目标（100 字）、偏好方式和五种头像配色。偏好方式可选结对练习、互相答疑、项目协作、打卡自习，或留空。保存后立即更新导航身份与预览，刷新、退出重登后仍保留。提供撤销未保存修改；登录用户名、角色、状态和密码不能通过资料接口变更，密码继续在“账号安全”修改。

联系邮箱保留原唯一约束，冲突时整次保存回滚。空邮箱存为 NULL，昵称、兴趣与简介允许留空，拒绝控制字符；Vue 以文本渲染用户内容。头像使用内置颜色和昵称首字，无外链图片或文件上传。

## 好友学伴

学生导航新增“好友学伴”。输入关键词即可模糊查找有效学生，点击“添加学伴”。“收到的申请”支持同意与婉拒，“发出的申请”支持撤回。“我的学伴”显示已确认关系，可在页面内确认后移除。两个方向使用同一条关系，反向发送申请不会直接建立好友，必须由接收方明确同意。

学伴卡片只展示用户 ID、用户名、昵称、简介、兴趣、专业方向、年级、学习目标、偏好方式和头像配色，列表另含关系和申请时间。学习属性均由本人自愿填写，可清空；不能把未填属性当成实际身份。不会公开邮箱、密码、会话、个人情绪历史或课堂统计。好友关系不会扩大任何课堂数据权限，也没有增加私信、文件分享、在线状态或消息推送。本阶段教师和管理员不使用学生学伴入口。

按追加需求，0.8.0 开放公开学习资料的模糊搜索；不显示自己、停用账号或其他角色。关键词默认跨用户名、昵称、兴趣、简介、专业、年级、学习目标和偏好方式匹配，也可限定字段。最多 5 组空格分隔关键词，必须每组均匹配；兴趣、专业、年级、偏好方式、关系与共同课程筛选再同时满足。共同课程以双方课堂名单所属课程判断，包含已结束课程，不返回对方课程、班级或名单细节。空白搜索必须至少提供一项条件。

搜索每页 12 位，接口最多 24 位，按用户名、ID 固定排序；返回总数。百分号、下划线与反斜杠作为普通文字处理，不作为通配符，SQL 使用参数。旧的 username 参数继续支持完整用户名匹配。查找每人每 5 分钟最多 60 次，发送每人每小时最多 20 次（包括重复尝试），每人累计学伴和待处理关系最多 200 条。达到上限先撤回或处理已有申请。列表手动刷新，切换页面后重新读取；未接入实时消息。

## 数据与接口

user_profiles 是 users 的可选一对一扩展，无资料账号首次读取返回空值与默认配色。0.8.0 启动时在事务中检查旧资料表，补加专业、年级、学习目标与偏好方式列，不重建用户、不清除已填资料。buddy_connections 用排序后的 low_user_id/high_user_id 唯一约束避免双向重复，以 requester_id 区分申请方向。PENDING 只有接收方可变为 ACCEPTED；婉拒、撤回或移除删除该关系并写入审计，新申请使用新的自增 ID，旧页面中的请求 ID 不会处理后来的申请。所有关系写入使用事务，检查当前用户与对象状态。

| 接口 | 功能 |
| --- | --- |
| GET /api/users/me | 当前账号与个人资料 |
| PUT /api/users/me | 完整保存可编辑资料 |
| GET /api/buddies | 学伴、收到与发出的申请 |
| GET /api/buddies/search?q=... | 多关键词、字段范围与组合属性筛选；limit/offset 分页 |
| POST /api/buddies/requests | 向 user_id 发送申请 |
| POST /api/buddies/requests/{id}/accept | 接收方同意 |
| DELETE /api/buddies/requests/{id} | 撤回或婉拒待处理申请 |
| DELETE /api/buddies/{user_id} | 移除已确认学伴 |

写操作沿用会话登录、Origin 与 X-Requested-With 校验；资料和申请操作留审计，不在审计详情中保存邮箱或简介。教师管理员访问学伴接口返回 403，第三方不可操作不属于自己的申请。

## 检查与本机体验

0.7.0 新增 17 项 Python 检查，0.8.0 新增 16 项搜索与迁移检查，完整 Python 检查共 135 项通过。新增范围包括中文模糊搜索、跨字段关键词、范围限制、组合属性与共同课程筛选、关系筛选、通配符转义、分页和旧表增列保留资料。前端内存交互检查覆盖新增资料保存、组合条件传递、分页和清空条件，以及原有申请流程。构建通过。检查不等于真实浏览器验收。

本机更新前已保存数据库备份，增量初始化仅增加两个表。真实 HTTP 验证了资料持久化和收到申请的列表；演示课程、课堂和 192 条模拟反馈数量未改变。本机另创建 demo_buddy 演示学生“小禾（演示学伴）”，向 demo_student 发送一份待处理邀请，便于体验同意与婉拒；没有预先替用户接受。账号密码单独交给使用者，不随源码包分发。

0.8.0 更新前再次备份数据库，并只给原先没有资料的六个演示学生补充带“演示”昵称的学习属性。通过真实 HTTP 验证“设计”、组合“Python + 计算机 + 大二 + 项目协作 + 共同课程”和“学习目标：四级”的查找。已有用户、密码哈希、邮箱、已填资料、申请关系及课程反馈数量均核对保留。演示属性不代表真实学生资料。
