# 课堂请假（0.20.0）

学生进入“请假申请 → 申请请假”，按课程、北京时间日期选择尚未结束的一节课堂，填写病假/事假/其他及 2～500 字原因。也可从课程详情的具体课堂点击“申请请假”，或从日常课堂点击“本节课申请请假”，自动定位课堂。每份申请对应一节课，需要多节课请假时分别提交。

学生只看自己的申请，可按课程/状态筛选和分页。待审批申请需二次确认后撤回；已同意或驳回的申请不能撤回。驳回或撤回后，在课堂结束前可新建申请，旧记录保留。已有待审批或同意记录时，不允许同一学生重复申请同一课堂。

任课教师在“请假审批”处理本人所授课堂的申请；教学工作台显示待审批数与入口。可同意或驳回，驳回必须填写原因，同意可选填回复（最多 500 字）。学生刷新即可看到处理结果、教师回复和处理时间。管理员“请假记录”可查全校记录，本入口只读，审批仍由任课教师完成。

教师/管理员读取的课堂名单显示“已准假”“请假待审批”标记，不包含请假原因。请假原因与回复仅返回本人、当前任课教师及管理员的请假接口，不放入公开问题卡、学伴资料、课表或教学总览。不在审计日志记录原因和回复正文。

审批不会移出课程或课堂名单，不会删除、补造或修改情绪评价，不作为自动考勤判定。课堂结束后不能新申请，但教师仍可处理已有申请。不会发送邮件或站外通知。

## 草稿与重试

请假或审批未保存时，切换栏目、退出或开发者模式换身份受保护；可先保存或放弃草稿。关闭页面有草稿提醒。重复提交使用同一个请求键；提交已成功但响应丢失时重试不重复创建。撤回和审批也可重试，同版本已由其他操作处理时返回冲突，草稿保留，放弃草稿后刷新再看最新结果。

## 保存与权限

新增 leave_requests 表保存课堂、申请人、类型、原因、状态、版本、审批人和时间。部分唯一索引约束每人每课堂最多一份待审批或已同意申请。普通启动自动建表，既有业务记录保持不变，不预置虚构请假记录。

GET /api/leaves 支持角色范围内的课程/课堂/状态筛选与分页；POST /api/leaves 仅学生；PUT /api/leaves/{id}/cancel 仅本人学生；PUT /api/leaves/{id}/decision 仅任课教师。写操作检查登录、角色、来源和请求头，读写均不接受客户端指定申请人或审批人。

测试见 tests/test_leaves.py、tests/test_leave_interactions.cjs。真实浏览器还需检查日期选择、长原因换行、窄屏表单、键盘操作和学生/教师双账号刷新后的结果。
